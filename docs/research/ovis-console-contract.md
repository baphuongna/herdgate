## 3. Asset URL namespace and network cuts

- Current upstream `index.html:26-42` has root-scoped `/manifest.webmanifest`, `/favicon*`, `/apple-touch-icon.png`, `/src/main.tsx`, and `/src/pwa.ts`; it also has the external social metadata `https://ovis.sh/assets/og-icon.png` at `:13`. L1 serves the Console app at the **origin root `/`** on its separate loopback origin; root-scoped local URLs are therefore expected (with PWA/worker URLs removed), not a `/console/` app mount. `vite.config.ts:35-55` builds Vite output with its defaults and dev proxies `/api` and `/ws` to localhost:7317 (`:45-52`). That dev proxy is not a production integration.
- Imported font CSS uses relative source URLs (`src/fonts/fonts.css:1-32`); Vite fingerprints emitted fonts/assets under `/assets/` (comment at `:5-8`). In the current root build, app imports/icons/styles are bundled, while HTML and runtime worker still reference root paths. For L1, test the build with root base `/` and serve only manifest-listed local files. If root-base asset URLs prove unsuitable, an **asset-only URL prefix** may be evaluated independently; it does not change the app URL or origin-root mount. `/console/` is only a possible future Gate S4 subpath, not an L1 dependency. No runtime Ovis CDN/font fetch is evidenced by the font stylesheet, but browser network isolation still needs an actual browser test before claiming “no upstream requests”.
- `src/pwa.ts:11-25` can unregister workers/caches for bundled apps and register `/sw.js` for ordinary Ovis web pages. `public/sw.js` contains application cache, relay persistence, push and telemetry flows. For Herdgate L1: omit `src/pwa.ts`, worker source/registration, manifest, push, telemetry, relay/account shell, OAuth, updater and hosted app boot. Shell/API responses `no-store`; hash assets only may be immutable. Omit the Ovis social image URL and any absolute upstream URL reachable from retained components; use a static endpoint/source scan plus browser request interception later.
- Relative asset URL policy: no external font, icon, update or API URL; CSS `url()`/imports resolve to the root-base Vite `/assets/` manifest or to a separately validated asset-only prefix. Do not trust source-level `assets.externalRuntimeAssets: []` in the fixture as a network test—it is a policy expectation, not measured browser evidence. The fixture records `/` as L1 app base and `/console/` as Gate S4-only.

## 5. Typed fixture and honest integration proof

`test/fixtures/local-web-console-contract.json` captures the pinned contract and a synthetic runtime/session/pane-screen. `mirrorViewModel` in `src/console/web/view-model.ts` projects workspace/tab/pane labels while preserving upstream IDs; only a screen with the selected pane ID and current runtime generation becomes `ansi-snapshot`. A valid truncated screen remains displayable with `truncated:true` so the eventual renderer can warn; nullable source dimensions pass through unchanged. Missing screen, unavailable runtime, wrong pane/generation, or missing pane stays an explicit non-success. This fixture is only seam proof: it does **not** replace the full Ovis frontend target, model an Ovis relay, use a real Herdr socket, issue network calls, render ANSI in a browser, or claim a production endpoint exists.

The test file asserts the boot-mode/API/asset contract and the fake view-model behavior. It is evidence that Herdgate's typed integration seam can express the correct distinction, not evidence that Ovis builds, that Herdr CLI/RPC/pipe supports pane reads, that Windows works, or that browser network isolation has been verified.
