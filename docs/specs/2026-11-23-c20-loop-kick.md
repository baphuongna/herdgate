# Spec C20 — Loop `kick` + auto-resume khi file theo dõi đổi

Ngày: 2026-11-23 · Vòng: DEV-LOOP (worktree `c20`, branch `c20-loop-kick`) ·
Chủ đề: hai đường nạp việc cho loop mà không phải `stop`+`start` (mất pane
đang có đáp án).

## Bối cảnh

- Hôm nay để loop thấy backlog mới, owner phải `stop` + `start`: pane cũ
  (cùng đáp án cuối, cùng context phiên) bị đóng. C11c đã chứng minh
  `start` từ chối khi pane còn sống đúng để BẢO VỆ pane ấy — nên "đổi việc
  = mất pane" là nghịch lý vận hành: bảo vệ pane mà không có lối nạp việc.
- Cần hai đường: (a) `kick` — owner resume + nudge NGAY khi muốn; (b) khi
  loop TỰ pause (C17 ghi `pausedBy:"auto"`) và file được theo dõi (backlog)
  đổi → tự resume: owner sửa file là tín hiệu duy nhất, không bấm gì.
- Pause của owner (action `pause`) là quyết định người — máy không bao giờ
  đè lên: phân biệt bằng `pausedBy`.

## Tính năng

1. Action `kick` (manifest: id `kick`, title `herdgate-loop: resume and
   nudge now`) + `cmdKick`:
   - pane chết (`paneAlive` sai) → exit 1, `pane <id> is gone — start a
     new loop`.
   - `pane.list` báo `agent_status` `working|blocked` → KHÔNG gõ (không
     chen ngang), out `{ok:true, nudged:false, reason:"working"}`, exit 0.
   - còn lại: xoá `paused`, `pausedBy`, `noopStreak`; gửi nudge text NGAY
     (bypass cooldown một lần); `cycles+1`, `lastNudgeAt=now`; log
     `kick: nudged pane <id>`; out `{ok:true, nudged:true, paneId}`.
2. Config thêm `watchFiles` (tuỳ chọn): mảng 1–8 đường dẫn TUYỆT ĐỐI, mỗi
   entry phải tồn tại và là FILE (không thư mục) → validate fail-closed
   như mọi input owner.
3. Action `pause`: ghi `pausedBy:"owner"` + `pausedAt:Date.now()`, giữ
   `noopStreak` nguyên; `resume` xoá `pausedBy` (+`pausedAt`).
4. `cmdEvent` khi settle pane mình mà `s.paused===true`:
   `shouldAutoResume(s, cfg)` đúng khi `s.pausedBy==="auto"` VÀ cfg có
   watchFiles VÀ `max(mtimeMs(watchFiles)) > (s.pausedAt ?? 0)` → resume
   (paused false, xoá pausedBy), log `auto-resume: watched file changed —
   <basename>`, rồi đi tiếp logic nudge thường (cooldown vẫn tôn trọng).
   `pausedBy==="owner"` hoặc undefined → KHÔNG bao giờ tự resume; log
   `paused by owner — no auto-resume` (mỗi settle 1 dòng).
5. `status` lộ `watchFiles` (mục config), `pausedBy`, `pausedAt` (mục state).

## Thiết kế

- `getPane(paneId)`: một lượt `pane.list` trả nguyên pane object (kick cần
  cả `agent_status`); `paneAlive` giữ nguyên chữ ký, đọc qua `getPane` —
  status/start không đổi hành vi.
- `latestWatchedChange(state, cfg)`: trả đường dẫn file có mtimeMs lớn
  nhất > `pausedAt ?? 0` (null nếu không có — gồm cả khi file biến mất:
  statSync throw coi như "không đổi", event hook không crash);
  `shouldAutoResume(state, cfg)` là predicate bọc ngoài, ĐÚNG TÊN để
  controller gộp với C17 (C17 ghi cùng trường `pausedBy:"auto"` lúc tự
  pause — chỉ cần case `auto` + `owner`/undefined khớp hợp đồng).
- Kick không validate config: thao tác chủ động của owner, chỉ đọc
  `nudgeText` null-safe (thiếu/hỏng → DEFAULT_NUDGE); không chặn.
- Auto-resume xoá `pausedBy` (theo spec, giữ pausedAt — paused:false làm
  nó vô nghĩa); resume tay xoá cả pausedAt cho hygiene.

## Rủi ro

- Gộp C17: cả hai vòng đụng `pausedBy` — C17 GHI `auto`, C20 ĐỌC để quyết
  định resume; logic gọn trong 2 hàm riêng, không đụng đường ghi của C17.
- Kick đang working trả `nudged:false` exit 0 — caller TUI phải đọc out,
  không xem exit code là "đã kick".
- watchFiles trỏ file bị xoá sau khi validate → statSync throw được nuốt
  (coi "không đổi") — không treo event hook.
